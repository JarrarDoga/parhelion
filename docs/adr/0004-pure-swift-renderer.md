# 0004: Draw in pure Swift, show frames in a separate window host

- **Status:** Accepted
- **Date:** 2026-10-20
- **Supersedes:** [0002](0002-defer-renderer-backend.md)

## Context

ADR 0002 listed the requirements for the renderer: draw into a native window on Wayland and X11,
draw off-screen frames that other tools can embed or stream, render text well enough to judge a
layout, and build in CI without a GPU.

Two later constraints narrowed the options:

- [ADR 0003](0003-no-swiftpm-resources.md): the root package cannot ship SwiftPM resources, because
  xtool packages every target's resource bundle when it builds an app for iOS.
- The root package also cannot depend on system C libraries. A `systemLibrary` target for SDL3 or
  FreeType would make `swift build` fail for every contributor and every app that lacks those
  headers, including apps that only build for iOS.

We checked availability on 2026-10-20. SDL3 is packaged for Fedora 44 and for Ubuntu 26.04
("resolute"), but not for Ubuntu 24.04 ("noble"). The official Swift 6.3 images exist only for
noble and jammy, so a C dependency in the root package would also drop Swift 6.3 from CI.

## Decision

Parhelion draws frames in pure Swift, in a new `ParhelionRender` module with no dependencies:

- A TrueType parser reads Inter's outlines (`glyf`, `loca`, including composite glyphs) as well as
  its metrics. Layout and drawing share it, so measured and drawn text agree.
- An exact-area anti-aliasing rasterizer fills paths, following the approach of font-rs.
- A canvas composites shapes and text into an RGBA buffer at any scale, and encodes PNG with a
  small built-in deflate encoder.
- The font is compiled into the module as base64 source, generated by `Scripts/embed-font.sh`.

The window is a separate program. The app process renders frames off screen and sends them to a
window host over a local socket; the host shows them with SDL3 and sends mouse and keyboard input
back. The host lives in its own package under `Tools/`, so only people who build the window host
need SDL3.

## Consequences

- Every frame is an off-screen frame. Screenshots, tests, agents, and embedding in other tools
  all work without a display or a GPU, on every Swift version CI tests.
- Rendering is deterministic: the same tree produces the same pixels on every machine, because no
  system font library or GPU driver is involved. Pixel tests are stable.
- The renderer draws only what layout supports today: rectangles, text, and placeholder symbols.
  Rounded rectangles and ellipses exist in `Path` for upcoming views. There is no hinting,
  kerning, or shaping, so complex scripts do not render correctly yet.
- Drawing on the CPU costs a few milliseconds per frame at 2× scale. That is enough for a preview
  that redraws when state changes. A GPU backend can replace the rasterizer later without changes
  to views, layout, or the window protocol.
- The embedded font adds about 550 KB of source.
